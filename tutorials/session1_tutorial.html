1 RNA-seq Background

1.1   What is RNA-seq and why do we use it?

Every cell in your body contains the same DNA, but not every gene is active at the same time — or in the same cell type. Gene expression is the process of reading a gene from DNA into messenger RNA (mRNA), which is then translated into protein. RNA sequencing (RNA-seq) measures the abundance of every mRNA molecule in a sample simultaneously, giving you a genome-wide snapshot of which genes are active and at what level.

Why RNA-seq?

  • Unbiased — no need to know in advance which genes to measure
  • Quantitative — read counts reflect expression level
  • Reproducible — short-read sequencing is highly standardized
  • Widely supported — a large ecosystem of analysis tools exists

In this workshop we use RNA-seq to track gene expression across three stages of human iPSC differentiation into spinal motor neurons: Day 0 (iPSC), Day 13 (motor neuron progenitor), and Day 28 (mature motor neuron).

1.2   From biology to data: the wet lab workflow

The journey from a cell to sequencing data involves several steps:

  1. RNA extraction — cells are lysed and total RNA is purified
  2. mRNA selection — poly-A selection or ribo-depletion enriches for mRNA and removes ribosomal RNA (which would otherwise dominate the library)
  3. Fragmentation — mRNA is broken into ~200–500 bp fragments, since sequencers read short stretches of sequence
  4. Reverse transcription — RNA fragments are copied into complementary DNA (cDNA) using reverse transcriptase
  5. Adapter ligation — short DNA sequences are added to both ends of each fragment so they can bind to the sequencing flow cell
  6. PCR amplification — the library is amplified to generate enough material
  7. Sequencing — the Illumina sequencer reads one or both ends of each fragment (single-end or paired-end), producing FASTQ files

Paired-end sequencing reads both ends of each fragment, giving more information about the insert and improving alignment accuracy. This dataset uses paired-end 150 bp reads.

1.3   What is a FASTQ file?

After sequencing, each sample is delivered as one or two FASTQ files (two for paired-end). A FASTQ file stores millions of short reads, where each read occupies four lines:

@SRR11951474.1 1/1                         ← read name
ACGTACGTACGTACGTACGTACGTACGTACGT           ← DNA sequence
+                                           ← separator
IIIIIIIIIIIIIIIIIIIIIIIIIIIIIIII           ← quality scores (Phred)

The quality score encodes how confident the sequencer is about each base call. Higher = more confident. Poor-quality bases at the ends of reads are trimmed before alignment.

1.4   The bioinformatics workflow: FASTQ to count matrix

The computational side of RNA-seq has two stages:

Upstream (this tutorial — run on Tufts HPC via OOD nf-core/rnaseq app):

FASTQ files
    ↓  Quality control (FastQC, MultiQC)
    ↓  Adapter trimming (Trim Galore)
    ↓  Alignment to reference genome (STAR)
    ↓  Quantification (Salmon)
    ↓
Count matrix  (salmon.merged.gene_counts.tsv)

Downstream (Part 2 tutorial — run in RStudio app on OOD):

Count matrix
    ↓  Normalization + QC (DESeq2, VST)
    ↓  Differential expression (DESeq2)
    ↓  Visualization (volcano, heatmap, PCA)
    ↓  Enrichment analysis (GO, KEGG)
    ↓
Biological interpretation

  • Design: 3 biological replicates × 3 timepoints = 9 samples total

Motor neurons — the cells that connect the spinal cord to muscles — are selectively lost in ALS and spinal muscular atrophy. This differentiation protocol generates the cell type most relevant to these diseases from patient stem cells, making it a powerful experimental model.

Rather than using a traditional command-line SSH connection, Tufts provides Open OnDemand — a browser-based interface that lets you access the HPC, manage files, and launch interactive apps (RStudio, Jupyter, nf-core pipelines) without leaving your web browser.

Use lab storage — not your home directory. Your home directory has only 30 GB of storage. RNA-seq data and pipeline outputs can easily exceed this, causing jobs to fail and potentially disrupting others. Always work from your lab's shared storage, typically at a path like /cluster/tufts/[labname]/[username]/.

If you are not affiliated with a lab or do not have access to lab storage, contact tts-research@tufts.edu to request allocation.

3 Unix Basics

3.1   Why Unix for bioinformatics?

Most bioinformatics tools run on Linux/Unix systems. The HPC cluster runs Linux, and you interact with it through a command-line shell (typically Bash). You do not need to be a programmer — a small set of commands covers the vast majority of what you will do.

The shell follows a simple pattern:

command  [options]  [arguments]

For example: ls -lh /home/username runs the ls command with the -l (long format) and -h (human-readable file sizes) options on the path /home/username.

4 nf-core/rnaseq Pipeline

4.1   What is Nextflow and nf-core?

Nextflow is a workflow management system for running multi-step bioinformatics pipelines. Instead of running each tool (FastQC, STAR, Salmon, MultiQC, ...) manually and keeping track of outputs, Nextflow chains them together automatically, handles job submission to SLURM, and restarts from the last successful step if something fails.

nf-core is a community that builds and maintains well-tested, standardized Nextflow pipelines. nf-core/rnaseq is one of the most widely used pipelines in the field — it handles the entire upstream workflow from FASTQ to count matrix.

Key benefits:

  • Fully automated: submit one job and get the count matrix back
  • Reproducible: the exact version of every tool is recorded
  • Containerized: tools run inside containers so the software environment is standardized
  • Quality-controlled: MultiQC report summarizes QC for all samples in one page

4.2   What the pipeline does

nf-core/rnaseq runs these steps automatically:

StepToolWhat it does
Quality control FastQC Checks read quality, adapter content, and duplication rate per sample
Adapter trimming Trim Galore Removes adapter sequences and low-quality bases from read ends
Alignment STAR Maps trimmed reads to the human reference genome (GRCh38)
Quantification Salmon Counts reads per gene using the STAR alignments
QC aggregation MultiQC Summarizes all QC metrics across all samples into one interactive report
Output — salmon.merged.gene_counts.tsv — the count matrix for Part 2

4.3   The SLURM submission script

SLURM is the job scheduler on the Tufts HPC. When you submit a job, SLURM queues it and allocates compute resources when they become available. You submit jobs with sbatch.

Open run_rnaseq.sh and examine its two parts:

Part 1 — SLURM directives (lines starting with #SBATCH) tell SLURM how many resources to allocate to the head job (the Nextflow process itself, not the heavy compute steps):

#SBATCH --job-name=nfcore_rnaseq
#SBATCH --partition=batch
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
#SBATCH --time=48:00:00
#SBATCH --output=nfcore_rnaseq_%j.out
#SBATCH --error=nfcore_rnaseq_%j.err

The log files (nfcore_rnaseq_[jobid].out and .err) will be written to your current working directory where you run sbatch.

Important: The head job only runs Nextflow itself — it uses modest resources (4 CPUs, 16G RAM). Nextflow then automatically submits all the heavy steps (STAR alignment, Salmon quantification, etc.) as separate SLURM child jobs. The --time=48:00:00 gives the pipeline up to 48 hours to complete all child jobs.

Part 2 — The nextflow run command:

nextflow run nf-core/rnaseq \
    -revision 3.26.0 \
    -profile tufts \
    -resume \
    --input          samplesheet.csv \
    --outdir         rnaseq_output \
    --genome         GRCh38 \
    --aligner        star_salmon

The two most important parameters to understand:

ParameterMeaning
--input samplesheet.csv The samplesheet listing all your samples and FASTQ file paths. Each row is one sample. The pipeline reads this to know which files to process. Make sure this file is in your current working directory, or provide the full path.
--outdir rnaseq_output The directory where all pipeline results will be saved — alignment files, count matrices, QC reports, and logs. Remember this path: everything you need after the run is here.

Other key parameters:

ParameterValueMeaning
-revision3.26.0Pins the exact pipeline version for reproducibility
-profiletuftsLoads Tufts HPC–specific resource settings
-resume—If interrupted, restart from the last successful step (saves hours)
--genomeGRCh38Use human reference genome (hg38)
--alignerstar_salmonAlign with STAR, quantify with Salmon
--skip_deseq2_qctrueSkip built-in DESeq2 QC — we do this in Part 2

4.4   Submit the job

Make sure you are in your working directory (where samplesheet.csv and run_rnaseq.sh live), then submit:

# Confirm you are in the right place
pwd
ls -lh

# Submit the job to SLURM
sbatch run_rnaseq.sh

SLURM will print a job ID:

Submitted batch job 12345678

Save this number — you will use it to monitor the job.

Key things to check in the MultiQC report:

MetricWhat to look for
% Uniquely mapped readsShould be >75% for a clean human sample
Total readsAll samples should have comparable library sizes
% DuplicatesModerate duplication (<50%) is expected for RNA-seq
% Adapter contentShould be near 0% after trimming

If any sample shows a very low mapping rate or dramatically lower read count, flag it before running Part 2. A bad sample in the count matrix will distort your downstream results.
