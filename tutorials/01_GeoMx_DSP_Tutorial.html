1 Introduction

1.1 What is GeoMx DSP?

The NanoString GeoMx Digital Spatial Profiler (DSP) measures gene expression in specific regions of a tissue section while preserving spatial context. Instead of homogenizing a whole tumor, you can ask: “What genes are expressed in the tumor cells versus the immune microenvironment?”

Key concepts:

Term Meaning
ROI Region of Interest — a user-drawn area on the slide (your sampling unit)
AOI Area of Illumination — a sub-region within an ROI, e.g., tumor cells vs. immune cells
Segment The profiled unit; one ROI can contain multiple segments (Tumor, TME)
WTA Whole Transcriptome Atlas — ~18,000 human or ~21,000 mouse genes
Negative probes Controls targeting sequences absent from the genome; used to estimate background

A key feature of GeoMx in tumor biology is morphology-based segmentation: using cell-type markers (e.g., pan-cytokeratin for tumor, CD45/CD3/CD68 for immune), you can separate the tumor compartment from the tumor microenvironment (TME) within the same ROI and profile them independently.

GeoMx Workflow:

   Tissue section
       │
       ├── Morphology staining (DAPI + marker antibodies)
       │
       ├── Draw ROIs → sub-segment into Tumor / TME masks
       │
       ├── UV light cleaves barcoded probes per segment
       │
       └── Sequencing → Count matrix (genes × segments)

   Result: Expression profiles for Tumor AND Immune compartments
           from the same tissue region

1.3 Dataset Used in This Tutorial

We use the NSCLC (non-small cell lung cancer) GeoMx dataset distributed with the SpatialDecon Bioconductor package. This is a real published dataset consisting of:

  • 191 ROIs arrayed in a dense grid across a 7.8 × 6.7 mm NSCLC tumor
  • Each ROI split into a Tumor segment and a Microenvironment (TME) segment → 382 total AOIs
  • ~1,700 genes profiled (including 544 genes from the SafeTME immune cell matrix)
  • Nuclei counts per segment (allows estimating cell numbers)

This is a human dataset; the workflow is identical for canine, feline, or equine tumors — only genome annotations change.

7 Differential Expression: Tumor vs. Microenvironment

7.1 What is limma and Why Use It?

limma (Linear Models for Microarray and RNA-seq data) is an R package for testing differential expression. For every gene, it fits a linear model — essentially asking: “Can I explain this gene’s expression as a function of my experimental groups?”

For example, for the gene VEGFA:

VEGFA expression = Baseline + (Effect of being in Tumor segment) + Error

If the tumor effect is large and consistent across ROIs, the gene is flagged as differentially expressed.

7.1.1 Why not just a t-test?

You could test each gene with a simple t-test, but with small sample sizes the variance estimates become unstable — some genes will look significant just because they happen to have low variance by chance. limma solves this with empirical Bayes moderation: it borrows information across all genes to stabilize variance estimates, pulling unreliable estimates toward the average. This dramatically reduces false positives with small n.

7.1.2 What the output columns mean

Column Meaning
logFC log2 fold change. A value of 1 = 2× higher in Tumor; –1 = 2× higher in TME
AveExpr Average expression across all segments
P.Value Raw p-value for the test
adj.P.Val P-value corrected for multiple testing (FDR). Use this, not the raw p-value

7.1.3 limma vs. dream — which to use?

Scenario Use
Each segment comes from a different animal limma
Same animal contributes multiple segments or slides (e.g., primary + metastatic) dream from variancePartition

dream handles random effects — it knows that two segments from the same animal are correlated and accounts for that, increasing power and reducing false positives. See the Adapting This Workflow section at the end for a dream example.

7.1.4 The paired design

In this dataset, every ROI contributes exactly one Tumor segment and one TME segment. These are paired observations — they come from the same physical tissue location. Including roi_id in the model tells limma about this pairing, so it can control for ROI-to-ROI variation in tissue biology and focus only on the Tumor vs. TME difference.

7.2 Filter and Prepare

# Keep genes expressed above background in ≥ 10% of segments
# This removes genes that are essentially undetected across the dataset

cat("Genes retained for DE:", nrow(expr_de), "\n")
Genes retained for DE: 1700 
# Build design matrix
# segment_type: Tumor vs. TME — TME is the reference (baseline)
# roi_id: blocking factor — controls for paired ROI structure
meta <- annot_filt |>
  rownames_to_column("Segment") |>
  mutate(
    segment_type = factor(AOI.name, levels = c("TME", "Tumor")),
    roi_id       = factor(ROI)
  )

design <- model.matrix(~ segment_type + roi_id, data = meta)

7.3 Run limma

# Step 1: fit the linear model to each gene
fit <- lmFit(expr_de, design)

# Step 2: apply empirical Bayes moderation (stabilises variance estimates)
fit <- eBayes(fit)

# Step 3: extract results for the Tumor vs. TME contrast
# coef = "segment_typeTumor" means: effect of being Tumor vs. the reference (TME)
# Positive logFC = higher in Tumor; Negative logFC = higher in TME
de_res <- topTable(fit, coef = "segment_typeTumor",
                   number = Inf, sort.by = "P") |>
  rownames_to_column("Gene") |>
  mutate(
    # A gene is "significant" if FDR < 5% AND fold change > 2× (|logFC| > 1)
    Significant = adj.P.Val < 0.05 & abs(logFC) > 1,
    Direction   = case_when(
      Significant & logFC > 0 ~ "Tumor-high",
      Significant & logFC < 0 ~ "TME-high",
      TRUE ~ "NS"
    )
  )

8 Pathway and Gene Set Enrichment Analysis

A list of DE genes by itself tells you which genes differ. Pathway analysis tells you what biology those genes represent — are they involved in cell proliferation? Immune evasion? Angiogenesis?

We use two complementary approaches:

Method Input Question
ORA (Over-Representation Analysis) A list of significant DE genes Are my DE genes enriched in known pathways more than expected by chance?
GSEA (Gene Set Enrichment Analysis) All genes ranked by fold change Which pathways are systematically up or down, even among genes that didn’t cross the significance threshold?

ORA is simpler and easier to interpret. GSEA is more sensitive — it uses the full ranked list so it doesn’t depend on an arbitrary significance cutoff. For small panels (~1,700 genes like this dataset), GSEA often finds signal where ORA finds nothing, because ORA requires enough significant genes to fill a pathway.

Both methods compare your genes against gene sets — curated lists of genes known to be involved in specific biological processes. We use two databases:

  • GO (Gene Ontology): Hierarchical catalogue of biological processes, molecular functions, and cellular components. Very broad coverage.
  • MSigDB Hallmark: 50 well-defined, coherent biological states (e.g., HALLMARK_INFLAMMATORY_RESPONSE, HALLMARK_EPITHELIAL_MESENCHYMAL_TRANSITION). Less redundant than GO, easier to interpret.

run_ora <- function(gene_ids, universe_ids, title_label) {
  for (pcut in c(0.05, 0.1, 0.2)) {
    res <- enrichGO(
      gene          = gene_ids,
      universe      = universe_ids,
      OrgDb         = org.Hs.eg.db,
      ont           = "BP",
      pAdjustMethod = "BH",
      pvalueCutoff  = pcut,
      qvalueCutoff  = 1,     # don't double-filter
      readable      = TRUE
    )
    if (!is.null(res) && nrow(as.data.frame(res)) > 0) {
      message(title_label, ": ", nrow(as.data.frame(res)),
              " GO terms at FDR < ", pcut)
      return(res)
    }
  }
  message(title_label, ": no enriched GO terms found at any threshold.")
  return(NULL)
}

8.2 Gene Set Enrichment Analysis (GSEA)

GSEA ranks all tested genes by a score that combines fold change direction and statistical confidence:

rank score = sign(logFC) × -log10(p-value)
  • High positive score → strongly and significantly higher in Tumor
  • High negative score → strongly and significantly higher in TME
  • Near zero → not different between groups

GSEA then asks: for a given pathway (e.g., HALLMARK_ANGIOGENESIS), are its member genes concentrated at the top or bottom of this ranked list? If they cluster at the top, the pathway is enriched in Tumor; if at the bottom, enriched in TME.

The key output is the NES (Normalized Enrichment Score):

  • NES > 0 → pathway enriched in Tumor (positive end of the ranked list)
  • NES < 0 → pathway enriched in TME (negative end)
  • Larger absolute NES = stronger enrichment

9 Cell Type Deconvolution of the Microenvironment

9.1 What is Deconvolution?

Remember that each GeoMx segment — even a “TME” segment — is still a mixture of cell types. Your TME segment contains T cells, macrophages, B cells, fibroblasts, endothelial cells, and more, all profiled together as one bulk expression measurement.

Deconvolution computationally estimates what fraction of that bulk signal comes from each cell type. It works by comparing your segment’s expression profile against a reference matrix of known cell type signatures — essentially asking: “What mixture of these cell types, when combined, would produce the expression profile I observed?”

Your TME segment expression  ≈  w₁ × (T cell profile)
                               + w₂ × (Macrophage profile)
                               + w₃ × (Fibroblast profile)
                               + w₄ × (B cell profile) + ...

Deconvolution solves for: w₁, w₂, w₃, w₄ ... (the weights/abundances)

This is powerful because it tells you, for example, that one patient’s TME is 40% macrophages while another’s is 40% T cells — without needing to physically separate those cells.

Limitation: deconvolution is an estimate, not a measurement. Its accuracy depends on how well the reference profiles match your species and tissue type. For veterinary species, human reference profiles can still work reasonably well for conserved immune cell types (T cells, macrophages), but results should be validated with IHC or flow cytometry when possible.

The SpatialDecon package uses the SafeTME matrix — a curated reference of immune and stromal cell expression profiles designed specifically to avoid genes commonly expressed by cancer cells, reducing contamination of immune estimates by tumor signal.

# Introduction

## What is GeoMx DSP?

The **NanoString GeoMx Digital Spatial Profiler (DSP)** measures gene expression in specific regions of a tissue section while preserving spatial context. Instead of homogenizing a whole tumor, you can ask: *"What genes are expressed in the tumor cells versus the immune microenvironment?"*

**Key concepts:**

| Term | Meaning |
|------|---------|
| **ROI** | Region of Interest — a user-drawn area on the slide (your sampling unit) |
| **AOI** | Area of Illumination — a sub-region within an ROI, e.g., tumor cells vs. immune cells |
| **Segment** | The profiled unit; one ROI can contain multiple segments (Tumor, TME) |
| **WTA** | Whole Transcriptome Atlas — ~18,000 human or ~21,000 mouse genes |
| **Negative probes** | Controls targeting sequences absent from the genome; used to estimate background |

A key feature of GeoMx in tumor biology is **morphology-based segmentation**: using cell-type markers (e.g., pan-cytokeratin for tumor, CD45/CD3/CD68 for immune), you can separate the **tumor compartment** from the **tumor microenvironment (TME)** within the same ROI and profile them independently.


# Differential Expression: Tumor vs. Microenvironment

## What is limma and Why Use It?

**limma** (Linear Models for Microarray and RNA-seq data) is an R package for testing differential expression. For every gene, it fits a **linear model** — essentially asking: *"Can I explain this gene's expression as a function of my experimental groups?"*

For example, for the gene *VEGFA*:

```
VEGFA expression = Baseline + (Effect of being in Tumor segment) + Error
```

If the tumor effect is large and consistent across ROIs, the gene is flagged as differentially expressed.

### Why not just a t-test?

You could test each gene with a simple t-test, but with small sample sizes the variance estimates become unstable — some genes will look significant just because they happen to have low variance by chance. limma solves this with **empirical Bayes moderation**: it borrows information across *all* genes to stabilize variance estimates, pulling unreliable estimates toward the average. This dramatically reduces false positives with small n.

### What the output columns mean

| Column | Meaning |
|--------|---------|
| `logFC` | log2 fold change. A value of 1 = 2× higher in Tumor; –1 = 2× higher in TME |
| `AveExpr` | Average expression across all segments |
| `P.Value` | Raw p-value for the test |
| `adj.P.Val` | P-value corrected for multiple testing (FDR). **Use this, not the raw p-value** |

### limma vs. dream — which to use?

| Scenario | Use |
|----------|-----|
| Each segment comes from a different animal | `limma` |
| Same animal contributes multiple segments or slides (e.g., primary + metastatic) | `dream` from `variancePartition` |

`dream` handles **random effects** — it knows that two segments from the same animal are correlated and accounts for that, increasing power and reducing false positives. See the *Adapting This Workflow* section at the end for a `dream` example.

### The paired design

In this dataset, every ROI contributes exactly one Tumor segment and one TME segment. These are **paired observations** — they come from the same physical tissue location. Including `roi_id` in the model tells limma about this pairing, so it can control for ROI-to-ROI variation in tissue biology and focus only on the Tumor vs. TME difference.

## Filter and Prepare

# Pathway and Gene Set Enrichment Analysis

A list of DE genes by itself tells you *which* genes differ. Pathway analysis tells you *what biology* those genes represent — are they involved in cell proliferation? Immune evasion? Angiogenesis?

We use two complementary approaches:

| Method | Input | Question |
|--------|-------|---------|
| **ORA** (Over-Representation Analysis) | A list of significant DE genes | Are my DE genes enriched in known pathways more than expected by chance? |
| **GSEA** (Gene Set Enrichment Analysis) | All genes ranked by fold change | Which pathways are systematically up or down, even among genes that didn't cross the significance threshold? |

ORA is simpler and easier to interpret. GSEA is more sensitive — it uses the full ranked list so it doesn't depend on an arbitrary significance cutoff. For small panels (~1,700 genes like this dataset), GSEA often finds signal where ORA finds nothing, because ORA requires enough significant genes to fill a pathway.

Both methods compare your genes against **gene sets** — curated lists of genes known to be involved in specific biological processes. We use two databases:

- **GO (Gene Ontology):** Hierarchical catalogue of biological processes, molecular functions, and cellular components. Very broad coverage.
- **MSigDB Hallmark:** 50 well-defined, coherent biological states (e.g., `HALLMARK_INFLAMMATORY_RESPONSE`, `HALLMARK_EPITHELIAL_MESENCHYMAL_TRANSITION`). Less redundant than GO, easier to interpret.

## Over-Representation Analysis (ORA)

ORA works like a Fisher's exact test for each pathway: given that X% of all tested genes belong to pathway P, is the fraction of *your* DE genes in pathway P significantly higher than that?

```{r}
#| label: ora-setup

# Tumor-high genes (expressed higher in tumor)
tumor_up <- de_res |> filter(Direction == "Tumor-high") |> pull(Gene)

background <- de_res$Gene

cat("Tumor-high DE genes:", length(tumor_up), "\n")

# Helper: run ORA with progressive fallback on p-value cutoff
run_ora <- function(gene_ids, universe_ids, title_label) {
  for (pcut in c(0.05, 0.1, 0.2)) {
    res <- enrichGO(
      gene          = gene_ids,
      universe      = universe_ids,
      OrgDb         = org.Hs.eg.db,
      ont           = "BP",
      pAdjustMethod = "BH",
      pvalueCutoff  = pcut,
      qvalueCutoff  = 1,     # don't double-filter
      readable      = TRUE
    )
    if (!is.null(res) && nrow(as.data.frame(res)) > 0) {
      message(title_label, ": ", nrow(as.data.frame(res)),
              " GO terms at FDR < ", pcut)
      return(res)
    }
  }
  message(title_label, ": no enriched GO terms found at any threshold.")
  return(NULL)
```
```{r}
}
```

## Gene Set Enrichment Analysis (GSEA)

GSEA ranks **all** tested genes by a score that combines fold change direction and statistical confidence:

```
rank score = sign(logFC) × -log10(p-value)
```

- High positive score → strongly and significantly higher in Tumor
- High negative score → strongly and significantly higher in TME
- Near zero → not different between groups

GSEA then asks: for a given pathway (e.g., `HALLMARK_ANGIOGENESIS`), are its member genes concentrated at the top or bottom of this ranked list? If they cluster at the top, the pathway is enriched in Tumor; if at the bottom, enriched in TME.

The key output is the **NES (Normalized Enrichment Score)**:

- **NES > 0** → pathway enriched in Tumor (positive end of the ranked list)
- **NES < 0** → pathway enriched in TME (negative end)
- Larger absolute NES = stronger enrichment

```{r}
#| label: gsea
#| cache: true

# Rank all genes: positive values = higher in tumor, negative = higher in TME
ranked <- de_res |>
  mutate(rank_score = sign(logFC) * -log10(P.Value)) |>
  arrange(desc(rank_score)) |>
  filter(!duplicated(Gene)) |>
  pull(rank_score, name = Gene)

# Convert to Entrez IDs
entrez_map  <- bitr(names(ranked), fromType = "SYMBOL", toType = "ENTREZID",
                    OrgDb = org.Hs.eg.db)
ranked_e    <- ranked[entrez_map$SYMBOL]
names(ranked_e) <- entrez_map$ENTREZID

# Hallmark gene sets (MSigDB)

  mutate(entrez_gene = as.character(entrez_gene))

  geneList     = sort(ranked_e, decreasing = TRUE),
```

# Cell Type Deconvolution of the Microenvironment

## What is Deconvolution?

Remember that each GeoMx segment — even a "TME" segment — is still a **mixture of cell types**. Your TME segment contains T cells, macrophages, B cells, fibroblasts, endothelial cells, and more, all profiled together as one bulk expression measurement.

**Deconvolution** computationally estimates what fraction of that bulk signal comes from each cell type. It works by comparing your segment's expression profile against a **reference matrix** of known cell type signatures — essentially asking: *"What mixture of these cell types, when combined, would produce the expression profile I observed?"*

```
Your TME segment expression  ≈  w₁ × (T cell profile)
                               + w₂ × (Macrophage profile)
                               + w₃ × (Fibroblast profile)
                               + w₄ × (B cell profile) + ...

Deconvolution solves for: w₁, w₂, w₃, w₄ ... (the weights/abundances)
```

This is powerful because it tells you, for example, that one patient's TME is 40% macrophages while another's is 40% T cells — without needing to physically separate those cells.

**Limitation:** deconvolution is an estimate, not a measurement. Its accuracy depends on how well the reference profiles match your species and tissue type. For veterinary species, human reference profiles can still work reasonably well for conserved immune cell types (T cells, macrophages), but results should be validated with IHC or flow cytometry when possible.

The `SpatialDecon` package uses the **SafeTME matrix** — a curated reference of immune and stromal cell expression profiles designed specifically to avoid genes commonly expressed by cancer cells, reducing contamination of immune estimates by tumor signal.
